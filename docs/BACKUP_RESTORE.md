# Backup and restore

## What a backup contains

`scripts/backup.sh` writes `backups/jp-backup-<UTC>/` (mode 700):

| File | Content | Why |
|---|---|---|
| `postgres.dump` | `pg_dump -Fc` of the platform database | users, orgs, projects, deployments, encrypted secrets, domains |
| `minio.tar.gz` | MinIO data volume | tenant storage buckets |
| `env.backup` (`.enc` with `BACKUP_PASSPHRASE`) | copy of `.env` | **contains `SECRETS_MASTER_KEY`** - without it stored secrets cannot be decrypted |
| `acme.tar.gz` | `traefik_acme` volume | avoids re-issuing certificates (Let's Encrypt rate limits) |
| `traefik_dynamic.tar.gz` | generated routers | convenience; regenerated by the domain service |
| `tenant-volumes/*.tar.gz` | with `--with-tenant-volumes`: add-on / managed-database volumes | optional, crash-consistent only |
| `registry.tar.gz` | with `--with-registry` | optional; images are normally rebuilt |
| `MANIFEST.sha256`, `backup.json` | checksums + metadata | integrity |

Not included: tenant application containers (redeploy), Redis (queues, rate limits, revocations), Docker images, the repository checkout.

The script **verifies** its own output (checksums, `pg_restore --list` must show table data, every tar is listed) and exits non-zero otherwise.

```bash
scripts/backup.sh --keep 7                          # keep the 7 newest
BACKUP_PASSPHRASE=... scripts/backup.sh             # encrypt env.backup
scripts/backup.sh --with-tenant-volumes
# nightly (cron):  15 3 * * *  cd /home/opc/cloud-plateform && scripts/backup.sh --quiet --keep 7
```

Copy backups off the server (`rsync`, object storage): a backup on the same disk does not survive disk loss.
Consistency: the database dump is transactionally consistent; MinIO and tenant volumes are file-level snapshots of running containers.

## Restore

```bash
scripts/restore.sh backups/jp-backup-20261103T031500Z            # asks to type 'restore'
scripts/restore.sh <dir> --restore-env --yes                     # new server: also installs the backed-up .env
```

Steps performed: verify checksums -> compare `SECRETS_MASTER_KEY` (refuses on mismatch unless `--restore-env`) -> stop services except
Postgres -> drop and recreate the database and `pg_restore` -> restore MinIO / Traefik volumes (and tenant volumes with
`--with-tenant-volumes`) -> start the stack -> wait for gateway health.

**Disaster recovery on a new server:** run `./install.sh` (or only install Docker and clone the repo), then
`scripts/restore.sh <backup> --restore-env --yes`. Redeploy projects afterwards (images and containers are rebuilt from Git).
Test your restore periodically - an untested backup is a hope, not a backup.
